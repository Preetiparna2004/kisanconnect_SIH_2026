WHAT IS KISANCONNECT?
----------------------
KisanConnect is a full-stack digital agriculture platform built for Smart India
Hackathon 2026. It directly connects farmers and FPOs (Farmer Producer
Organizations) with buyers (consumers, retailers, bulk buyers), eliminating
middlemen and ensuring farmers get fair prices for their produce.

KEY FEATURES:
  - Direct Farmer-to-Buyer marketplace (zero intermediaries)
  - AI-powered Crop Recommendation (soil + climate ML model)
  - Demand Forecasting (price & demand trend prediction)
  - Route Optimization (multi-stop delivery planning with live map)
  - Admin Approval workflow (crops go live only after admin review)
  - Flexible Handover (Home Delivery OR Farm-Gate Pickup with OTP)
  - Multilingual support (English, Hindi, Odia)
  - Weather integration (live weather for farmers)
  - Real-time farmer-buyer messaging

TECH STACK – WHAT WE USE AND WHY
================================================================================

BACKEND:
--------
1. Python (FastAPI)
   - WHY: Fastest Python web framework, auto-generates API docs (Swagger),
     async support, and easy integration with ML libraries.
   - WHERE: backend/ folder

2. SQLAlchemy (ORM)
   - WHY: Lets us write Python classes instead of raw SQL queries. Works with
     both SQLite (development) and PostgreSQL (production/Supabase).
   - WHERE: backend/models.py, backend/database.py

3. SQLite Database
   - WHY: Zero-config local database. File saved as kisanconnect.db.
     Can be migrated to PostgreSQL/Supabase for production.
   - WHERE: kisanconnect/kisanconnect.db (auto-created on first run)

4. Pydantic v2
   - WHY: Data validation and serialization. Ensures API inputs/outputs are
     always correct types and formats.
   - WHERE: backend/schemas.py

5. JWT (JSON Web Tokens) – python-jose
   - WHY: Secure, stateless user authentication. Token stored in browser,
     sent with every API request to verify identity.
   - WHERE: backend/routes/auth.py

6. Passlib + bcrypt
   - WHY: Securely hashes passwords. Never stores raw passwords in database.
   - WHERE: backend/routes/auth.py

7. Scikit-learn + NumPy + Pandas
   - WHY: ML library for AI crop recommendation model.
     RandomForest classifier trained on soil/climate data.
   - WHERE: backend/ai/

8. python-dotenv / pydantic-settings
   - WHY: Reads secret config (database URL, JWT secret) from .env file
     so secrets are never hardcoded in code.
   - WHERE: backend/config.py, backend/.env

FRONTEND:
---------
9. React 18 (with Vite)
   - WHY: Component-based UI library. Fast hot-module-reload in development.
     Industry standard for modern web apps.
   - WHERE: frontend/src/

10. React Router v6
    - WHY: Client-side routing (navigate between pages without full reload).
    - WHERE: frontend/src/App.jsx

11. Axios
    - WHY: HTTP client to call the backend API. Automatically attaches JWT
      token to every request via interceptors.
    - WHERE: frontend/src/services/api.js

12. Tailwind CSS
    - WHY: Utility-first CSS framework. Fast styling without writing custom CSS.
      Responsive design built-in.
    - WHERE: frontend/src/index.css, applied via className in all components

13. i18next (Internationalization)
    - WHY: Multilingual support. Translates the app to English, Hindi, Odia
      based on user preference.
    - WHERE: frontend/src/i18n.js, frontend/public/locales/

14. Leaflet (react-leaflet)
    - WHY: Free, open-source interactive maps (no API key needed).
      Used for Route Optimization delivery map.
    - WHERE: frontend/src/pages/RouteOptimization.jsx

15. React Hot Toast
    - WHY: Beautiful popup notifications for success/error messages.
    - WHERE: Used throughout all pages

16. Lucide React
    - WHY: Clean, consistent icon library. Used for all icons in the UI.
    - WHERE: Used in all components and pages

config.py
  → WHAT: Central settings file (app name, JWT secret, DB URL, CORS origins).
  → WHY:  Single place to control all configuration. Reads from .env file.

database.py
  → WHAT: Creates the SQLite database engine and session factory.
  → WHY:  Every API route calls get_db() from here to talk to the database.

models.py
  → WHAT: Defines all database tables as Python classes:
          - User (farmers, buyers, admin)
          - Crop (listings with price, quantity, category)
          - Order + OrderItem (purchase records)
          - Payment (payment tracking)
          - Message (farmer-buyer chat)
          - Feedback (ratings and reviews)
          - FarmerProfile (extended farmer info)
  → WHY:  SQLAlchemy ORM – write Python, not SQL.

schemas.py
  → WHAT: Pydantic models that define what data the API accepts and returns.
          E.g., UserCreate (to register), UserRead (to display user data).
  → WHY:  Auto-validates incoming requests and formats outgoing responses.

main.py
  → WHAT: The FastAPI app entry point. Registers all route routers,
          sets up CORS middleware, creates database tables on startup.
  → WHY:  The app starts here. uvicorn runs this file.

requirements.txt
  → WHAT: List of all Python packages needed.
  → WHY:  Run "pip install -r requirements.txt" to install everything at once.

auth.py
  → WHAT: /api/auth/register, /api/auth/login, /api/auth/me
  → WHY:  Handles user signup, login (returns JWT token), and get current user.
  → HOW:  POST /register with name+email+password → creates user account.
          POST /login with email+password → returns access_token for future calls.

crops.py
  → WHAT: All crop listing CRUD operations.
          GET  /api/crops/          → Public marketplace (APPROVED crops only)
          POST /api/crops/          → Farmer creates a new crop listing
          GET  /api/crops/my/listings → Farmer's own crops (all statuses)
          GET  /api/crops/{id}      → Single crop details
          PUT  /api/crops/{id}      → Update a crop
          DELETE /api/crops/{id}   → Delete a crop (farmer or admin)
          PATCH /api/crops/{id}/approval → Admin approves/rejects
  → WHY:  Core marketplace functionality. New crops start as PENDING until
          admin approves them.

orders.py
  → WHAT: Order placement and management.
          POST /api/orders/         → Buyer places an order
          GET  /api/orders/my       → Buyer sees their orders
          GET  /api/orders/farmer/incoming → Farmer sees orders for their crops
          PUT  /api/orders/{id}/status   → Update order status
  → WHY:  Manages the purchase flow from cart to delivery. Supports two
          handover methods: DELIVERY (home) or PICKUP (farm-gate with OTP).

admin.py
  → WHAT: Admin-only endpoints.
          GET /api/admin/stats           → Platform stats (users, crops, orders)
          GET /api/admin/crops/pending   → All crops awaiting review
          GET /api/admin/crops/all       → All crops (any status)
          GET /api/admin/users           → All registered users
          PATCH /api/admin/users/{id}/toggle-active → Activate/deactivate user
  → WHY:  Central management panel for admins to moderate the platform.

auth.py (auth guards)
  → require_role(role) → Restricts endpoints to specific roles (FARMER/BUYER/ADMIN)
  → get_current_user   → Decodes JWT token to identify who is making the request

farmers.py
  → WHAT: Farmer profile creation and viewing.
  → WHY:  Extended farmer info (land size, FPO membership, bio, certifications).

messages.py
  → WHAT: Farmer-buyer direct messaging.
  → WHY:  Allows buyers to ask farmers about crops without middlemen.

payments.py
  → WHAT: Mock payment intent creation and confirmation.
  → WHY:  Simulates UPI/payment gateway for demo purposes.

feedback.py
  → WHAT: Rating and review submission for farmers/crops.
  → WHY:  Builds trust by allowing buyers to rate their experience.

ai.py
  → WHAT: AI/ML endpoints:
          POST /api/ai/crop-recommend    → Soil data → crop recommendations
          POST /api/ai/demand-forecast   → Crop name → price/demand forecast
          POST /api/ai/route-optimize    → Destinations → optimized delivery route
  → WHY:  Core differentiator of the platform. Adds intelligent features.

================================================================================
USER FLOW WALKTHROUGH
================================================================================

FARMER FLOW:
  1. Register at /register → select "Farmer" role
  2. Login → redirected to /farmer-dashboard
  3. Go to "Add Crop" → fill form → submit (status: PENDING)
  4. Admin approves crop → crop goes LIVE on marketplace
  5. Buyers place orders → farmer sees in "Incoming Orders" tab
  6. Farmer can open Route Optimization → see all delivery addresses on map

BUYER FLOW:
  1. Register at /register → select "Buyer" role
  2. Browse /marketplace → search and filter crops
  3. Click crop → "Add to Cart"
  4. Go to /payment → choose Home Delivery or Farm-Gate Pickup
  5. For pickup: receive 4-digit OTP to show farmer
  6. Track order at /orders

ADMIN FLOW:
  1. Login as admin@kisanconnect.in
  2. Go to /admin → see platform stats
  3. Click "Pending Crops" → approve or reject with reason
  4. Click "All Crops" → delete any crop
  5. Click "All Users" → activate or deactivate accounts

================================================================================
IMPORTANT NOTES FOR THE TEAM
================================================================================

1. NEVER commit kisanconnect.db or .env to GitHub (they contain sensitive data).
   Both are already in .gitignore.

2. The backend MUST be running before the frontend can fetch any data.
   Start backend FIRST, then frontend.

3. Always run the backend from D:\Projects\SIH2026\kisanconnect (not from inside
   the backend folder). Wrong directory = ModuleNotFoundError.

4. If you see "ECONNREFUSED" in the Vite terminal, it means the backend is not
   running. Restart it with: python -m uvicorn backend.main:app --reload

5. To reset the database and start fresh with demo data:
   python seed.py   (run from kisanconnect folder)

6. View all API endpoints with interactive testing at:
   http://127.0.0.1:8000/docs  (Swagger UI)
